# 演出と盤面の再設計（2026-10-21）

Phase 1 の M5 で「最後に入れる」としていた演出（[phase1-plan.md](phase1-plan.md) の「宣言の吹き出し、解決の光・ダメージの演出」）を、
カードゲームらしい動きとして入れ直す。あわせて盤面の見た目をプレイマットの卓に寄せる。

参考: [f/pokemon-tcg](https://github.com/f/pokemon-tcg)（MIT）の `public/ui.js`。
取り入れたのは考え方（ゴーストを飛ばす・光弾 → 着弾 → スタンプの順・ヒットストップ・揺れ）で、コードはこのプロジェクトに合わせて書き直した。

## 1. 何を演出するか

| 出来事（`GameEvent`） | 演出 |
|---|---|
| `zoneChange` 手札 → スタック（唱える） | カードの写しが手札からスタックの小窓へ弧を描いて飛ぶ。着くと光る |
| `zoneChange` スタック → 戦場 / 手札 → 戦場 | 写しが戦場の置き場所へ飛び、着地で沈み込む（輪の波紋） |
| `zoneChange` 戦場 → 墓地（破壊・死亡） | 赤く光って震え、ひびの閃光と破片が散り、縮みながら墓地の束へ落ちる |
| `zoneChange` → 追放 | 白く光って浮き上がり、光の粒になって消える。追放の束がある側はそこに小さく吸い込まれる |
| `zoneChange` 戦場 → 手札（バウンス） | 青い渦の輪が出て、浮き上がってから手札へ戻る（相手なら相手の手札の札へ） |
| `zoneChange` スタック → 墓地（解決したインスタント・ソーサリー） | 薄くなりながら墓地の束へ |
| `zoneChange` ライブラリー → 手札（引く） | ライブラリーの束から手札へ飛ぶ |
| 新しいスタックの項目（対象あり） | 発生源から対象へ、弧を描く太い白い矢印（縁取りの胴と三角の頭）を引く（「対象に取った」の印）。胴が伸び、頭が対象の上で弾んで止まる |
| `resolved`（対象あり） | 発生源から対象へ光弾。色はカードの色（赤は炎、青は水、黒は紫、緑は葉、白は金、無色は銀） |
| `resolved`（立ち消え） | 発生源で煙のように消える |
| `damage`（戦闘） | 攻撃クリーチャーが対象へ踏み込み、着弾 |
| `damage` | 着弾: 閃光・星形の弾け・衝撃の輪・対象の揺れ。クリーチャーには「−N」のスタンプ |
| `life`（減る） | LIFE の札が揺れ、「−N」のスタンプ、数が数え下がる |
| `life`（増える・回復） | 緑の光の輪と立ち上る粒、「+N」のスタンプ、数が数え上がる |
| `tapped` | 横向きに回る（アンタップは戻る） |
| `counters` | カウンターの数をカードの上にスタンプ |
| 終局（クリア / 失敗） | 画面の中央に大きなスタンプ |
| 同じ領域の中で位置が変わったカード | 他の演出が終わった後に、新しい位置へ滑る（FLIP） |

演出の順は、エンジンが返した出来事の順（`StepResult.events`）。1 回の回答で返る出来事をまとめて、拍（beat）の列にして順に再生する。

## 2. 仕組み

盤面は回答のたびに作り直す（`play.ts` の `render` が `replaceChildren` する）。差分の描画ではないので、演出は「前の DOM の写し」と「後の DOM」を使う。

```
onSession(新しい StepResult)
  ├─ capture(root)   … 描き直す前に、カードとプレイヤーの位置・要素を控える（Snapshot）
  ├─ render()        … 新しい状態を描く
  └─ play(snapshot, 前の GameView, 後の GameView, 新しい出来事)
       1. 領域が変わったカード: 後の要素を隠し、前の位置に写し（ゴースト）を置く
          同じ領域で位置が変わったカード: CSS の translate で前の位置に留めておく
       2. 出来事を拍にして順に再生（光弾・着弾・スタンプ・移動の演出）
       3. 留めていたカードを新しい位置へ滑らせる
       4. 写しを消し、隠した要素を出す
```

- 動かすのは CSS の個別の変形プロパティ（`translate` / `rotate` / `scale`）。手札の扇・タップの傾きが使っている `transform` と合成されるので、元の見た目を壊さない。
- 写し・光弾・スタンプは `body` 直下の固定の層（`.fxlayer`）に置く。盤面を作り直しても消えない。
- 再生中は層が入力を受け止める（盤面を押せない）。**層を押すと演出を飛ばす**（残りの拍を待たずに終わらせる）。
- 再生中に来た描き直し（エンジンの状態の変化など）は、再生が終わるまで待たせる。おまかせ（`quick.ts`）の次の回答も、再生が終わってから送る。
- 位置が分からないもの（相手の手札のカード、見えない領域）は、束・要約の札（`data-pile`）を行き先・出どころにする。

### 設定

- ヘッダーの「演出」で入切。端末に覚える（`mtgp.motion`）。
- OS の「視差効果を減らす」（`prefers-reduced-motion: reduce`）なら既定で切る。
- 切っているときは今まで通り、変わったカードを短く光らせるだけ。

## 3. 盤面の見た目（再設計）

参考のゲームと同じく「卓の上にカードを置いている」見た目に寄せる。配置（上に相手、下に自分、左に束、浮かぶ小窓）は変えない。

| 部分 | 変更 |
|---|---|
| 盤面 | プレイマットの面（中央が明るい放射のグラデーションと、薄い格子の模様）。明るい画面・暗い画面とも同じトークンで |
| 自分・相手の側 | 枠線の箱をやめ、マットの上の区画（半透明の面と柔らかい影）。手番の側は縁が光る |
| カード | 影を付けて卓から少し浮かせる。ホバーで持ち上がる。選択の候補は脈打つ光の縁 |
| LIFE | 大きめの札にして、勝敗に直結する数を目立たせる |
| スタックの小窓 | 呪文の色の帯を見出しに付け、積まれている感じを出す |

## 4. 残すこと

- 相手の手札から唱えた呪文は、相手のアバターから出す（相手の手札は描いていないため）。
- 演出の速さの設定（倍速）は、使ってみて必要なら足す。
